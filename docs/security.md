# Честная модель безопасности

[English](security_EN.md)

Этот документ описывает **что плагин реально защищает, а что нет**. Он написан по
результатам аудита и намеренно не содержит обещаний абсолютной безопасности.

| Что НЕ проверялось | реальный MAX E2E, полный Hermes core, внешние ссылки, правила платформ, полная история секретов |

Обозначения достоверности (как в бэклоге): **S** — статическое сопоставление кода и
документов, **R** — изолированное выполнение с моками (не полный плагин), **E** —
реальная локальная команда, **V** — гипотеза или внешний контракт, требующий проверки.

> Отсутствие находки не означает отсутствия уязвимости. Плагин **не рассчитан** на
> публичный или многопользовательский контур до закрытия задач SEC-01…07.

## Модель доверия

| Сторона | Что предполагается | Ограничение |
|---|---|---|
| MAX Bot API | источник событий `message_created`, `message_callback`, `bot_started` | подлинность события подтверждается только секретом вебхука; в long polling — доверием к API |
| Пользователь/чат | идентификаторы берутся из события | авторизуются только по allowlist пользователей; для callback-подтверждений проверка неполная (SEC-01) |
| Ядро Hermes | получает текст и медиа и выполняет инструменты | плагин не является границей безопасности ядра |
| Сеть | любой URL вложения, пришедший в событии | фильтруется частично (см. таблицу ниже и SEC-02/SEC-03) |
| Хост шлюза | доверенный | файловая система, `.env` и порт вебхука защищаются вами, а не плагином |

## Безопасные значения по умолчанию и что нужно переопределить

| Настройка | По умолчанию | Риск | Что ставить |
|---|---|---|---|
| `MAX_ALLOW_ALL_USERS` | `false` | — | оставить `false` |
| `MAX_ALLOWED_USERS` | пусто | ⚠️ **пустой список при `MAX_ALLOW_ALL_USERS=false` не закрывает доступ**: любой, кто может написать боту, доходит до ядра (SEC-05/SEC-06) | обязательно указать свой MAX user_id |
| `MAX_CROSS_SESSION` | `true` | ⚠️ `/sessions` и `/resume` вне фильтра платформы; до закрытия SEC-05 выдаются заголовки/превью/ID сессий всех платформ | `false`, если ботом пользуется больше одного человека или к нему есть доступ из группы |
| `MAX_WEBHOOK_SECRET` | пусто | ⚠️ пустой секрет — только предупреждение в логе, обработка запросов продолжается; отправитель берётся из JSON (SEC-04) | обязателен в webhook-режиме + сетевые ограничения |
| `MAX_WEBHOOK_HOST` | `0.0.0.0` | ⚠️ порт слушает все интерфейсы | `127.0.0.1` за reverse proxy |
| `MAX_GROUP_POLICY` | `allowlist` | ⚠️ в политике `allowlist` пустой список даёт «разрешено», списки объединяются по OR (SEC-06) | `closed` либо заполнить оба списка |
| `MAX_TABLE_AS_IMAGE` | `false` | — | по необходимости |
| `MAX_AUTO_INSTALL_PLAYWRIGHT` | `false` | ⚠️ при `true` плагин в рантайме ставит пакет и браузер из сети | оставить `false`, если установка из сети не контролируется |
| `MAX_INSECURE_SSL` | `false` | ⚠️ при `true` отключается проверка TLS | только для локальных тестов |

### Минимальная конфигурация для одного владельца

```bash
# ~/.hermes/.env
MAX_BOT_TOKEN=<токен бота>
MAX_ALLOWED_USERS=<ваш MAX user_id>          # обязательно, иначе доступ открыт всем
MAX_CROSS_SESSION=false                       # пока SEC-05 не закрыт
MAX_WEBHOOK_SECRET=<длинная случайная строка> # обязательно в webhook-режиме
MAX_WEBHOOK_HOST=127.0.0.1                    # если перед шлюзом стоит reverse proxy
```

При такой конфигурации к боту имеет доступ один пользователь, входящих портов нет
(long polling), а история сессий других платформ не раскрывается. Дополнительно
ограничьте доступ к самому хосту: `.env` с токеном читается только владельцем.

## Webhook, ingress, firewall

- **Long polling (по умолчанию)** не требует входящих портов — это минимальная
  поверхность атаки. Если публичный ingress не нужен, оставляйте polling.
- **Webhook** требует публичного HTTPS: MAX подключается только на 443. TLS
  терминируется на reverse proxy (Caddy/Nginx/Traefik/Cloudflare Tunnel), а
  слушатель плагина биндится на `127.0.0.1:8646`.
- **Секрет вебхука** MAX присылает как сырое значение заголовка
  `X-Max-Bot-Api-Secret` (не HMAC-подпись); плагин сравнивает его через
  `secrets.compare_digest`. Пустой секрет **не** приводит к отказу от обработки —
  только к предупреждению (SEC-04), поэтому закрывайте контур сетевыми средствами.
- **Firewall**: порт `8646` не должен быть доступен извне. Разрешайте входящие 443
  только на reverse proxy, остальное — закрыто.
- **Встроенный rate limit** вебхука — 30 запросов / 10 секунд на IP, в памяти
  процесса: сбрасывается при перезапуске и не различает клиентов за прокси. Это
  защита от всплесков, а не от целенаправленной атаки.
- **`/health`** отдаётся без аутентификации и подтверждает только то, что процесс
  поднят (не готовность к обработке сообщений, см. CODE-05).

## Что реализовано — и насколько это проверено

| Защита | Состояние | Ограничение |
|---|---|---|
| Allowlist пользователей | S | пустой список доступа не закрывает (SEC-05/SEC-06) |
| Проверка URL входящих медиа (`_validate_download_url`) | S | отклоняются не-http(s) схемы, литеральные private/loopback/link-local/reserved/multicast/unspecified IP, `localhost`, `*.local`; **имена хостов, не являющиеся литеральным IP, принимаются без DNS-проверки**, приватный адрес за DNS не отсекается (SEC-03) |
| Белый список хостов для **исходящих** загрузок | S | применяется к отправке медиа на MAX (`*.max.ru`, `*.oneme.ru`, `*.cdn-max.ru`), не к входящим URL |
| Редиректы при загрузке медиа | S | HTTP-клиент создаётся с `follow_redirects=False`; при этом заголовок `Authorization` всё равно уходит на исходный URL вложения (SEC-02) |
| Сравнение секрета в постоянном времени | S | `secrets.compare_digest` |
| Права каталогов кэша | S | аудио-кэш и каталог PNG-таблиц создаются с `mode=0o700` (эффективный режим ограничен umask); права на отдельные файлы явно не выставляются |
| Очистка логов | S | из URL удаляются userinfo и query-строка (`_safe_url_for_log`), сам токен в логи не пишется; гарантии отсутствия секретов в текстах исключений сторонних библиотек нет |
| Лимит входящих медиа | S | 50 МБ относится к **отправке**; тело ответа GET буферизуется целиком, streaming-лимита и общего дедлайна нет (SEC-07) |
| CI-проверки | S | в `.github/workflows/ci.yml` есть ruff, pytest, bandit и pip-audit, но ruff/bandit покрывают `adapter.py`, `tests/`, `scripts/`, **не покрывают `mixins/`**; триггер — push/PR в `main`; фактическое выполнение на используемом runner не подтверждено |

## Известные проблемы (открыты на момент написания)

Полные формулировки и критерии приёмки — в `BACKLOG.md` (ветка `docs/audit-backlog`, commit `abd2f0f`).

| ID | Влияние на безопасность |
|---|---|
| SEC-01 | подтверждение опасной команды в группе может нажать другой участник (непустого user_id достаточно) |
| SEC-02 | токен бота отправляется на произвольный URL вложения, пришедший в событии |
| SEC-03 | скачивание медиа уязвимо к SSRF через DNS: приватные адреса за именем хоста не проверяются |
| SEC-04 | webhook без секрета не отказывает в обработке; `user_id` берётся из JSON запроса |
| SEC-05 | доступ к глобальным `/sessions` и `/resume`, утечка заголовков и превью сессий всех платформ |
| SEC-06 | семантика групповых списков: пустой список разрешает, объединение по OR |
| SEC-07 | нет лимита на объём и время входящих медиа (буферизация всего ответа) |

Пока эти задачи не закрыты, режимы использования следующие:

- **допустимо**: личное использование одним владельцем, long polling, allowlist
  заполнен, `MAX_CROSS_SESSION=false`, без публичного вебхука;
- **недопустимо**: публичный webhook без секрета и firewall, общий чат/группа с
  доступом к опасным инструментам, бот как общий сервис для нескольких владельцев.

## Отказ от гарантий

- Ни этот документ, ни прошлые аудиты не являются гарантией отсутствия уязвимостей.
- Перечисленные «реализованные защиты» проверены статически и частично моками, а не
  полным набором тестов или внешним аудитом.
- Ответственность за ingress, секреты, firewall, доступ к хосту и содержимое `.env`
  лежит на владельце развёртывания.
- До закрытия SEC-01…07 не используйте плагин в публичном или многопользовательском
  контуре.
