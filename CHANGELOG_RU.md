# Журнал изменений

Значимые изменения плагина hermes-max-integration.

## [Не выпущено]

- **Допуск при установке:** `tables` и `stt` теперь несут маркер core `sys_platform != 'android'`, а `playwright` объявлен диапазоном (`>=1.62,<2`) вместо точного пина `1.62.0`, конфликтовавшего с пином core в extra `google-meet` — плагин снова включается на текущем core, а будущее повышение pin в core ломает CI, а не установку у пользователя. `scripts/setup-playwright.py` принимает любую версию из диапазона. [DEP-001–004](docs/specs/20261030-install-admission-markers_RU.md).

- **Групповой доступ:** проверка групповой политики перед всеми callback кнопок; групповые/webhook поля Desktop, корректные числовые примеры ID, безопасные значения первой настройки и документация по ID, семье и смешанным группам. [GRP-001–004](docs/specs/20261022-group-access_RU.md).

- **Диагностика сессий:** явные причины выбора Core/picker, безопасные логи, read-only проверка dispatch после установки, настройка владельцев в manifest/Desktop и уточнение MAX_CROSS_SESSION. Пользователь подтвердил все живые сценарии на c5e41ac. [SLP-007–008](docs/specs/20261021-session-list-policy_RU.md).

- **Список сессий:** лимит по умолчанию 10 и настраиваемый режим MAX/все платформы; исправлены маршрутизация `/sessions all`, фильтрация до LIMIT, сохранение параметров refresh и соответствие длинного списка кнопкам. [SLP-001–006](docs/specs/20261021-session-list-policy_RU.md).

- **Передача каталога на ревью:** исходный [PR #137501](https://github.com/NousResearch/hermes-agent/pull/137501) обновлён на immutable v2.11.0 (commit `1321548cfe`), описание и ответ ревьюеру актуализированы; PR готов к повторному ревью. Временный #138075 закрыт как дубликат. Решение ревью ожидает. [MS-012](docs/specs/20261013-catalog-review-137501_RU.md).

## [2.11.0] — 2026-10-14

Сравнено с неизменяемым тегом `v2.10.2` (`bcbf7696a99e81db1679671f979726d5b5c2833b`). Этот релиз объединяет все изменения после указанной версии. [Сравнение с v2.10.2](https://github.com/Realmagnum/hermes-max-integration/compare/v2.10.2...v2.11.0).

### Добавлено

- **Ответы агента MAX только с файлом:** публичный hook `transform_llm_output` добавляет первое имя файла до доставки Core; прямая отправка вложений использует basename либо `File`, сохраняя авторский текст. Инструкции платформы объясняют финальный ответ `MEDIA:<absolute-file-path>`. Пользователь подтвердил живую доставку файла 2026-10-14. [CAP-001–005](docs/specs/20261013-media-caption_RU.md).
- **Презентация и документация:** баннер, компактная таблица возможностей с иконками и существующий пример PNG-таблицы в обоих README; заметки об архитектуре, контракты Micro-Spec, доказательства приёмки и передача работы.
- **Совместимость теста clarify:** регрессия реального tool result использует публичный single-question API minimum/baseline Core и batch API более позднего Core.
- **Регрессионные проверки:** реальные Core send-router и clarify queue, доступ и безопасность каталожного плагина, приватность диагностики, привязка model picker к инициатору и Desktop locale harness.

### Исправлено

- **Изоляция профилей:** токен MAX и webhook secret читаются через scoped-secret helper Core; default multiplex запускается без заимствования credentials другого профиля. Проверки зависимостей пассивны.
- **Интерактивные вопросы:** callbacks передают текст варианта синхронному resolver clarify Core, однократно продолжают ожидающий ход и поддерживают Other с вводом текста. Некорректные/чужие/повторные callbacks не потребляют действующий вопрос; каждый вариант занимает отдельную строку кнопок. Model picker/clarify проверены в живом чате.
- **Model picker:** привязывается к инициатору до отправки, требует совпадения prompt message, отклоняет неизвестного владельца и предлагает Cancel; в группе владелец не назначается первым нажатием.
- **Нативные подтверждения команд:** адаптер реализует execution-approval entry point Core и проверяет реально предложенные варианты и инициатора. Выбор execution approval в живом чате ещё не проверен.
- **Приватная настройка и доступ:** сохраняются существующие allowlists; запрещённые медиа, команды, callbacks и bot-start events отклоняются до скачивания и передачи в Core.
- **Результаты доставки:** отсутствующие файлы, ошибки upload/send и частично доставленные вложения возвращают неполную доставку с количеством файлов и сведениями об уже доставленном тексте/вложениях.
- **Локализация Desktop:** английский по умолчанию, русский language pack, перевод строк UI и даты по локали; ограничения старых SDK описаны.
- **Идентичность платформы:** резервное создание адаптера больше не изменяет enum maps Platform в Core.

### Изменено

- **Граница Core:** удалены `scripts/apply-core-fix.py` и инструкции запуска. Плагин не переписывает Core. Прямые CLI/cron media-only запросы без output hook по-прежнему требуют текста от вызывающего кода.
- **MAX API и TLS:** API endpoint — `platform-api2.max.ru`. Российский корневой сертификат ограничен API/upload клиентами; скачивание вложений сохраняет стандартное доверие TLS, allowlist хостов и SSRF/DNS-защиту.
- **Поддерживаемое окружение:** Hermes Core **>=0.21.4**, Python **>=3.12**; Python 3.11 исключён. В CI закреплены точные minimum/baseline/current версии Core; Playwright закреплён на 1.62.0, зависимости ограничены, PyYAML включён в test extras.
- **Операционные инструменты:** диагностика не читает файлы credentials и не раскрывает токены/тела API; установка Playwright сообщает ошибки. CI отклоняет сообщения fallback при установке зависимостей вместо проверки только exit status валидатора.
- **Документация:** английские основные файлы и переводы `_RU.md`, согласованная навигация и обновлённые внешние утверждения; выполненное отражено в changelog/specs, остатки — в backlog. README оставляет настройки в docs и возвращает наглядность v2.10.2.

### Проверки и ограничения

- Полный набор плагина: **796 passed** на Core `ca13a7828acd2ba8c75e1c1d1694cbc1aee7df3f`; последующее изменение инструкции: **27 профильных тестов passed**. Wheel включает helper подписей. Прежние проверки released-minimum Core 0.21.4/Python 3.12 сохраняются как датированные доказательства; CI точного релизного кандидата даёт обновлённые доказательства по матрице.
- Пользователь подтвердил живую доставку файла, model picker и clarify; осмотр Desktop EN/RU/дат записан. Финальный admission удалённого источника, живой выбор execution approval остаются открытыми.
- Аудит закреплённого в CI Core PyJWT 2.13.0 сообщает **14 advisories**. Исключений уязвимостей и несовместимых подмен нет; это незакрытое условие релиза.
- **CAT-01 / MS-006:** статичное английское описание в Capabilities → Plugins привязано к установленной сборке Desktop `0.0.0`, коммит `7157422022ff06f3e632d1dd394ee1253b17ad37` (проверено 2026-10-14); доказательства загрузчика/renderer и условия повторной проверки после обновления — в [возможностях Desktop](docs/features_RU.md). Это отдельная проблема от перезагрузки палитры на старых SDK. Визуальная приёмка остаётся закрытой. [Оставшиеся задачи](BACKLOG_RU.md).

## [2.10.0] — 2026-09-29

### Безопасность и доступ
- **SEC-01:** exec/slash/clarify callbacks проверяют владельца, чат, сообщение и TTL; политика первого нажатия group model picker остаётся отдельным пунктом CODE-06.
- **SEC-02/03:** входящее медиа защищено DNS pinning; клиент загрузки не пересылает `Authorization` недоверенным хостам.
- **SEC-04:** webhook требует секрет, кроме явного loopback-only режима разработки; секрет проверяется до чтения тела.
- **SEC-05:** кроссплатформенные сессии выключены по умолчанию и доступны доверенным владельцам.
- **SEC-06:** allowlist групп fail-closed, условия пользователей и чатов объединяются через AND.
- **SEC-07:** ограничены размер и число вложений, общий объём, таймаут и параллелизм загрузки.

### Надёжность и транспорт
- **CODE-01:** polling использует backoff с jitter и учитывает `Retry-After`; 401 завершает polling без потока повторных ошибок.
- **CODE-02:** разбиение сообщений сохраняет пробелы, форматирование и fenced code blocks.
- **CODE-03:** streaming throttle изолирован по чату и сообщению; гарантирован flush.
- **CODE-04/06:** model picker поддерживает составные ID и проверки устаревших сообщений/повторных callbacks. В группе без владельца он назначается первым нажатием; строгая привязка к инициатору остаётся открытой.
- **CODE-05:** разделены health (`/health`), readiness (`/ready`) и metrics (`/metrics`).
- **CODE-07:** lifecycle закрывает фоновые задачи и HTTP-клиенты.
- **CODE-08:** ingress-очередь, параллелизм и dedup ограничены настройками.

### Документация и качество
- Сверены переменные окружения и `platforms.max`; удалены несуществующие параметры.
- Добавлены проверки языковых ссылок, версии и числа тестов. Точный счётчик берётся из pytest текущего checkout.

## [2.9.0] — 2026-08-17

### Рефакторинг
- Монолитный `adapter.py` разделён на `mixins/`; адаптер стал фасадом над компонентами базового состояния, таблиц, медиа, кнопок, webhook, сессий и standalone-отправки.
- Внутри `mixins/` применяются относительные импорты; из `adapter.py` — `.mixins.xxx`, иначе загрузчик Hermes может не найти модули.
- Удалены дублирующее состояние сообщений, неэффективные обращения к коллекциям и исключения без логирования.

### Безопасность и исправления
- Добавлена `_validate_download_url()` для блокировки private/loopback/link-local/reserved IP, `localhost` и `*.local`.
- Отключено следование redirect при загрузке, чтобы не передавать токен стороннему хосту.
- Добавлено предупреждение при пустом `MAX_WEBHOOK_SECRET`.
- Ошибки JSON обрабатываются конкретными типами исключений.
- WAV/FLAC/M4A перед загрузкой нормализуются в Ogg/Opus через ffmpeg; блокирующее чтение файла вынесено из event loop.
- PNG-рендерер использует кэш по тексту таблицы и движку.
- Документация переведена на схему English base + `_RU`.
