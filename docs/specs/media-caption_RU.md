## Область и контракты

Использовать публичный hook `transform_llm_output` для ответов агента MAX до извлечения вложений Core. Добавлять подписи при прямой отправке адаптером и standalone sender. Сохранить авторский текст, другие платформы, ошибки доставки, credentials и проверку файлов. Core не изменять. Прямой `hermes send` и маршруты cron, не вызывающие этот hook, по-прежнему требуют текста от вызывающего кода: плагин не перехватывает их ранний отказ Core. Для hook нужен `platform=max` от Core; неизвестная платформа остаётся без изменений.

| ID | Условие | Наблюдаемый результат / приёмка | Статус |
|---|---|---|---|
| CAP-001 | Подпись отсутствует или содержит только пробелы | Использовать basename, включая Windows paths, либо явное имя файла; не раскрывать каталог; без имени использовать `File` | Запланировано |
| CAP-002 | Есть авторский текст | Сохранить его точно; отправку только текста не менять | Запланировано |
| CAP-003 | Ответ агента MAX содержит только MEDIA markers | Публичный hook добавляет первое имя файла до извлечения медиа Core; реальный public router принимает текст с файлом; другие платформы и ответы с подписью не меняются | Запланировано |
| CAP-004 | Адаптер/standalone отправляет вложение без подписи | Payload вложения содержит резервную подпись; смысл ошибок и частичной доставки сохраняется | Запланировано |
