# Micro-Specs: Группа PICKER (Model Picker UX & State)

Стандарт: Micro-Spec («OpenSpec без OpenSpec»). Источник: план `2026-09-30_020817-max-model-picker-replace.md`.

---

### ID: PICKER-TRANS-01
* **Требование:** При выборе провайдера в `/model` старое интерактивное сообщение со списком провайдеров (`provider_msg_id`) гарантированно удаляется при показе списка моделей.
* **Условие:** Пользователь нажимает на кнопку провайдера (callback `model:provider:{slug}`).
* **Ожидаемый результат:** Вызывается `delete_message(provider_msg_id)`, отправляется новое сообщение с моделями, `provider_msg_id` очищается, а `model_msg_id` сохраняется в `_model_picker_state[chat_id]`. В чате не остаётся висеть старое сообщение с провайдерами.
* **Проверка:** `pytest -q tests/test_model_picker.py -k "test_provider_selection_deletes_old_message"` завершается с кодом 0.
* **Не входит:** Редактирование существующего сообщения через `PUT /messages` (MAX API нестабильно обновляет inline-кнопки в некоторых клиентах).

### ID: PICKER-TRANS-02
* **Требование:** Состояние `_model_picker_state` корректно обрабатывает сбои API удаления и создания, не теряя меню при частичном падении.
* **Условие:** Вызов `delete_message` завершился ошибкой (например, сообщение уже удалено пользователем) или последующий `_post_interactive` вернул `success=False`.
* **Ожидаемый результат:** Ошибка DELETE не блокирует отправку нового сообщения с моделями; при падении POST старый ID сообщения не затирается, исключая потерю навигации.
* **Проверка:** `pytest -q tests/test_model_picker.py -k "test_model_picker_error_recovery"` завершается с кодом 0.
* **Не входит:** Автоматический retry неудачной отправки сообщения более 1 раза.

### ID: PICKER-PAGE-01
* **Требование:** Переключение страниц моделей (`Next` / `Prev`) заменяет текущее сообщение с моделями на новую страницу без накопления сообщений.
* **Условие:** Пользователь нажимает кнопку пагинации `model:page:{slug}:{page}`.
* **Ожидаемый результат:** Предыдущее `model_msg_id` удаляется через `delete_message`, отправляется сообщение следующей страницы, в `model_msg_id` записывается новый ID.
* **Проверка:** `pytest -q tests/test_model_picker.py -k "test_model_pagination_replaces_message"` завершается с кодом 0.
* **Не входит:** Циклическая пагинация (с последней страницы на первую).

---

### ID: PICKER-BACK-01
* **Требование:** Нажатие кнопки «← Назад к провайдерам» удаляет сообщение с моделями и заново выводит список провайдеров.
* **Условие:** Пользователь нажимает callback `model:back`.
* **Ожидаемый результат:** `model_msg_id` удаляется, отправляется исходное интерактивное меню провайдеров, его ID сохраняется как `provider_msg_id`, а `model_msg_id` сбрасывается в `None`.
* **Проверка:** `pytest -q tests/test_model_picker.py -k "test_back_to_providers_replaces_message"` завершается с кодом 0.
* **Не входит:** Сохранение выбранной ранее страницы моделей при возврате назад.

---

### ID: PICKER-DONE-01
* **Требование:** При финальном выборе модели удаляются все интерактивные сообщения выбора и отправляется подтверждение обычным текстом без кнопок.
* **Условие:** Пользователь нажимает на кнопку конкретной модели (callback `model:pick:{slug}:{model}`).
* **Ожидаемый результат:** `delete_message` вызывается для текущего `model_msg_id` (и для `provider_msg_id`, если он оставался); отправляется текстовое подтверждение «Модель переключена на {model}»; ключ чата очищается из `_model_picker_state`.
* **Проверка:** `pytest -q tests/test_model_picker.py -k "test_model_picked_cleans_up_all_messages"` завершается с кодом 0.
* **Не входит:** Изменение системного промпта модели при переключении.
