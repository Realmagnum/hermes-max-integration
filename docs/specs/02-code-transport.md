# Micro-Specs: Группа CODE & TRANS (Качество кода, транспорт и стабильность)

Стандарт: Micro-Spec («OpenSpec без OpenSpec»).

---

### ID: CODE-POLL-01
* **Требование:** Long-polling цикл выполняет экспоненциальный backoff с jitter при ошибках сети и статусах 429/5xx, а также учитывает заголовок `Retry-After`.
* **Условие:** Опрос `/events` возвращает HTTP 429 с `Retry-After: 5` или серию 500/502/503.
* **Ожидаемый результат:** Адаптер выдерживает паузу в соответствии с `Retry-After` (плюс jitter); не производит спам запросами; при фатальной ошибке 401 останавливает цикл с явным статусом аутентификации.
* **Проверка:** `pytest -q tests/test_poll_backoff.py -k "test_polling_honors_retry_after_and_backoff"` завершается с кодом 0.
* **Не входит:** Динамическое изменение таймаута длинного опроса (`timeout` query param).

### ID: CODE-STREAM-01
* **Требование:** Состояние троттлинга стриминга (`pending_text`, таймеры) изолировано по составному ключу `(chat_id, message_id)`.
* **Условие:** Адаптер одновременно стримит ответы в два разных чата или в два разных сообщения.
* **Ожидаемый результат:** Обновления текста в одном чате не задерживают и не перезаписывают буферы другого чата; каждый поток выполняет PUT независимо.
* **Проверка:** `pytest -q tests/test_streaming_isolation.py -k "test_concurrent_streams_do_not_interfere"` завершается с кодом 0.
* **Не входит:** Анимация индикатора набора текста (typing indicator).

### ID: CODE-STREAM-02
* **Требование:** При завершении потока ответа оставшийся в буфере текст гарантированно отправляется финальным запросом (flush).
* **Условие:** Генерация LLM завершилась, но последний чанк попал под интервал троттлинга (таймер задержки ещё не истёк).
* **Ожидаемый результат:** Метод finalize/flush отменяет отложенный таймер и немедленно отправляет финальное сообщение со 100% текстом генерации.
* **Проверка:** `pytest -q tests/test_streaming_isolation.py -k "test_stream_finalize_forces_immediate_flush"` завершается с кодом 0.
* **Не входит:** Добавление метаданных о затраченных токенах в конец сообщения.

### ID: CODE-MODEL-01
* **Требование:** Адаптер корректно сериализует и парсит идентификаторы моделей, содержащие двоеточия (например `llama3:8b`, `deepseek/r1:free`).
* **Условие:** Пользователь выбирает в меню модель с двоеточием в имени, генерируя callback.
* **Ожидаемый результат:** Строка модели и провайдера однозначно разделяются без разбиения имени модели на части `('provider', 'llama3:8b')`.
* **Проверка:** `pytest -q tests/test_model_picker.py -k "test_model_id_with_colons_roundtrip"` завершается с кодом 0.
* **Не входит:** Запрос динамического списка моделей из внешних каталогов.

### ID: CODE-HEALTH-01
* **Требование:** Endpoint `/health` возвращает статус готовности (readiness) только при успешной регистрации вебхука в MAX API.
* **Условие:** Сервис вебхука запущен локально, но вызов `POST /subscriptions` в MAX API упал с таймаутом или ошибкой.
* **Ожидаемый результат:** `/health` возвращает статус `503 Service Unavailable` (`ready=false`); при успехе регистрации возвращает `200 OK` (`ready=true`).
* **Проверка:** `pytest -q tests/test_webhook_health_contract.py -k "test_health_reflects_subscription_readiness"` завершается с кодом 0.
* **Не входит:** Проверка доступности внешних сервисов Hermes Core из хелсчека.

### ID: CODE-QUEUE-01
* **Требование:** Входящая очередь сообщений ограничена максимальным размером (bounded queue) и сбрасывает дубликаты апдейтов.
* **Условие:** Всплеск нагрузки (burst) входящих событий или повторная доставка MAX API события с уже обработанным `event_id`.
* **Ожидаемый результат:** Повторные `event_id` отбрасываются до постановки в очередь воркеров; при переполнении очереди возвращается контролируемый backpressure (HTTP 429 для webhook).
* **Проверка:** `pytest -q tests/test_backpressure.py -k "test_duplicate_events_discarded_and_queue_bounded"` завершается с кодом 0.
* **Не входит:** Персистентное сохранение очереди событий в случае падения процесса.
