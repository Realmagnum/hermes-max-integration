## Intent and boundaries

Build a small, isolated test-stand subproject in this repository which can run a real Hermes gateway against a deterministic local substitute for the MAX service. It must test a clean upstream Core installation and plugin installation through Hermes' supported plugin CLI, not merely import the adapter or pass the existing unit suite. The simulated contract reflects current plugin expectations; changes in real MAX protocols are addressed only after they occur. No production bot token, real MAX recipient, production subscription or public webhook is needed. Existing unit/CI checks remain intact. A local simulator does not prove real MAX delivery or future protocol compatibility.

Implementation choices (server library, VM/LXC/container and CI scheduler) belong to the plan, not to these observable contracts. The stand must not expose test-control endpoints outside its isolated network. Do not weaken media URL, DNS/SSRF or authentication protections or patch Core solely to enable tests. Current API base URLs are hard-coded in several plugin modules, so the safe injection approach requires separate design and tests before implementation; a blanket environment override is not assumed.

## Evidence and handoff

No test has been executed for this contract. Existing `MockMaxAPI` is an in-process `httpx.MockTransport` fixture, not a standalone HTTP server; the current CI runs a pinned Core test matrix and plugin admission but not clean remote-source install with a running gateway. The stand must extend, not falsely relabel, this evidence. Next authorized step is implementation after review of the plan; do not infer completion from this document.
