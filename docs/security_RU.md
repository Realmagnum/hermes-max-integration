# Честная модель безопасности

Документ описывает, **от чего плагин защищает, а от чего — нет**. Он суммирует имеющиеся записи аудита и регрессионные тесты, но не гарантирует абсолютную безопасность.

## Статус и область проверки

| Параметр | Значение |
|---|---|
| Область | плагин `hermes-max-integration` (`adapter.py`, `mixins/`, скрипты и документация) |
| Базовый commit аудита | `b004c573318f1d5e521255531d1943cc8a8b8b90` (`main`) |
| Бэклог находок | `BACKLOG.md` (SEC-01…SEC-07, CODE-01…CODE-08) |
| Обновлено | 2026-10-12; версию и число тестов сверяйте с текущим checkout |
| Проверялось | статический анализ, изолированные тесты; актуальный статус pytest смотрите в CI |
| Не проверялось | production E2E с реальными пользователями, правила внешних платформ, история до форка |

Метки доказательств из бэклога: **S** — статическое сравнение кода и документации; **R** — изолированный запуск с mocks; **E** — выполненная локальная команда; **V** — гипотеза или внешний контракт, требующие проверки.

> Статус аудита и число тестов относятся к конкретным версиям. Перед развёртыванием сверяйтесь с актуальным бэклогом и CI.

## Модель доверия

| Сторона | Предположение | Ограничение |
|---|---|---|
| MAX Bot API | источник событий `message_created`, `message_callback`, `bot_started` | подлинность событий подтверждается webhook-секретом; при long polling подразумевается доверие к API |
| Пользователь/чат | идентификаторы берутся из события | доступ ограничен allowlist; callback-запросы проверяют владельца (SEC-01) |
| Hermes Core | получает текст и медиа, запускает инструменты | плагин не является границей безопасности для Core |
| Сеть | URL вложения из события может быть недоверенным | DNS-проверка и блокировка приватных IP (SEC-02/SEC-03) |
| Хост Gateway | доверенный | файловую систему, `.env` и порт webhook защищает владелец, не плагин |

## Безопасные значения по умолчанию

Setup по умолчанию оставляет доступ закрытым и сохраняет существующий allowlist, если оператор явно не выбрал allow-all. Закрытый пустой список запрещает входящие события до скачивания медиа и передачи в Core. Токены и webhook-секреты читаются из активного secret scope Hermes; отсутствующий секрет профиля не подменяется ключом другого профиля из окружения.

Встроенный российский корневой сертификат добавляется только клиентам MAX API и upload. Скачивание вложений использует обычное системное доверие с сохранением allowlist хостов, привязки к публичным IP и запрета redirects. Плагин не изменяет исходники Hermes Core; неподдерживаемая маршрутизация media-only считается ограничением API Core, а не поводом для локального патча.

| Настройка | По умолчанию | Риск | Рекомендация |
|---|---|---|---|
| `MAX_ALLOW_ALL_USERS` | `false` | — | оставить `false` |
| `MAX_ALLOWED_USERS` | пусто | ⚠️ пустой список закрывает доступ (fail-closed, SEC-05/SEC-06) | указать свой MAX user_id |
| `MAX_CROSS_SESSION` | `false` | ⚠️ кроссплатформенные сессии выключены (SEC-05) | оставить `false`; включать только для доверенных `MAX_CROSS_SESSION_USERS` |
| `MAX_WEBHOOK_SECRET` | пусто | ⚠️ webhook без секрета не запустится (fail-closed, SEC-04) | обязателен для webhook вместе с сетевыми ограничениями |
| `MAX_WEBHOOK_HOST` | `0.0.0.0` | ⚠️ слушает на всех интерфейсах | `127.0.0.1` за reverse proxy |
| `MAX_GROUP_POLICY` | `allowlist` | ⚠️ условия объединяются через AND; пустой список закрывает доступ (SEC-06) | `allowlist` с заполненными списками или `closed` |
| `MAX_TABLE_AS_IMAGE` | `false` | — | включать при необходимости |
| `MAX_AUTO_INSTALL_PLAYWRIGHT` | `false` | ⚠️ при `true` пакет и браузер устанавливаются из сети во время работы | оставить `false`, если установка не контролируется |
| `MAX_WEBHOOK_INSECURE_DEV` | `false` | ⚠️ разрешает webhook без секрета только на loopback | `false` в production; `true` только локально для разработки |

### Минимальная конфигурация одного владельца

```bash
# ~/.hermes/.env
MAX_BOT_TOKEN=<токен_бота>
MAX_ALLOWED_USERS=<ваш_MAX_user_id>
MAX_CROSS_SESSION=false
```

Для webhook дополнительно задайте `MAX_WEBHOOK_SECRET`; за reverse proxy задайте `MAX_WEBHOOK_HOST=127.0.0.1`.

При этих настройках доступ ограничен одним пользователем, а история сессий других платформ не раскрывается. Long polling не требует входящих портов. Ограничьте доступ к хосту: файл `.env` должен читаться только владельцем.

## Webhook, ingress и firewall

- **Long polling (по умолчанию)** не требует входящих портов. Если публичный ingress не нужен, используйте его.
- **Webhook** требует публичный HTTPS: MAX подключается к порту 443. TLS завершается на reverse proxy (Caddy/Nginx/Traefik/Cloudflare Tunnel), listener плагина — на `127.0.0.1:8646`.
- **Секрет webhook** передаётся в заголовке `X-Max-Bot-Api-Secret` как исходное значение, не HMAC-подпись. Плагин сравнивает его через `secrets.compare_digest`; неверный секрет даёт 403 до чтения тела (SEC-04).
- **Firewall:** порт `8646` не должен быть доступен извне. Разрешите входящий 443 только к reverse proxy.
- Встроенный **rate limit webhook** — 30 запросов за 10 секунд на IP в памяти процесса; он сбрасывается при перезапуске и не различает клиентов за proxy.
- **`/health`** доступен без аутентификации и подтверждает только работу процесса. Готовность проверяется через `/ready` (CODE-05).

## Реализованные меры и пределы проверки

| Защита | Проверка | Ограничение |
|---|---|---|
| Allowlist пользователей | S/R | пустой список запрещает доступ (fail-closed, SEC-05/SEC-06) |
| Проверка URL входящего медиа (`_validate_download_url`) | S/R | DNS pinning блокирует private/loopback/link-local IP и DNS rebinding (SEC-03) |
| Allowlist хостов загрузки | S | применяется к отправке медиа в MAX (`*.max.ru`, `*.oneme.ru`) |
| Изоляция токена при скачивании | S/R | клиент загрузки не передаёт токен произвольным URL (SEC-02) |
| Сравнение секрета за постоянное время | S | `secrets.compare_digest`; проверка до чтения тела (SEC-04) |
| Права каталогов кэша | S | аудио- и PNG-каталоги создаются с `mode=0o700` |
| Очистка логов | S | из URL удаляются userinfo и query; токен не логируется |
| Лимиты входящего медиа | S/R | лимиты на размер вложения (`MAX_INBOUND_MEDIA_MAX_BYTES`), общий объём (`MAX_INBOUND_MEDIA_TOTAL_BYTES`), таймаут (SEC-07) |
| CI и тесты | E | статусы pytest, ruff, bandit и pip-audit смотрите в CI; число зависит от revision |
