# Micro-Specs: Группа SEC (Безопасность и контроль доступа)

Стандарт: Micro-Spec («OpenSpec без OpenSpec»). Каждая спецификация описывает одно наблюдаемое поведение с детерминированным тестом приёмки.

---

### ID: SEC-AUTH-01
* **Требование:** Подтверждение опасной команды через callback кнопки разрешается только пользователю, инициировавшему запрос (owner), в том же чате.
* **Условие:** Пользователь B (или запрос из другого чата) нажимает inline-кнопку подтверждения команды, созданной пользователем A.
* **Ожидаемый результат:** Команда не выполняется; состояние сессии/approval не извлекается и не сбрасывается; в лог пишется предупреждение об отказе в авторизации.
* **Проверка:** `pytest -q tests/test_callback_auth.py -k "test_unauthorized_user_cannot_confirm_command"` завершается с кодом 0 (assert command not executed, approval state kept).
* **Не входит:** Проверка прав администратора чата на уровне MAX API.

---

### ID: SEC-AUTH-02
* **Требование:** Состояние ожидания подтверждения (approval state) имеет строгий TTL и автоматически аннулируется по истечении срока.
* **Условие:** Пользователь нажимает кнопку подтверждения команды позже сконфигурированного TTL (по умолчанию 300 секунд).
* **Ожидаемый результат:** Resolver возвращает отказ; команда не исполняется; просроченное состояние удаляется из памяти.
* **Проверка:** `pytest -q tests/test_callback_auth.py -k "test_expired_approval_callback_rejected"` завершается с кодом 0.
* **Не входит:** Отображение всплывающего алерта в клиенте MAX.

### ID: SEC-TOKEN-01
* **Требование:** При скачивании входящего медиа по произвольному URL заголовок `Authorization` с токеном бота передаётся только на явно доверенные домены MAX.
* **Условие:** Адаптер скачивает медиа-вложение, у которого URL ведёт на сторонний origin (например, `https://attacker.example.com/file.bin`).
* **Ожидаемый результат:** HTTP GET запрос выполняется без заголовка `Authorization`; токен бота не утекает во внешнюю сеть.
* **Проверка:** `pytest -q tests/test_download_token_leak.py -k "test_untrusted_host_receives_no_auth_header"` завершается с кодом 0.
* **Не входит:** Валидация содержимого самого скачиваемого файла.

### ID: SEC-SSRF-01
* **Требование:** Загрузка медиа по URL блокируется, если разрешённый DNS IP-адрес принадлежит частным, loopback, link-local сетям или IPv6-аналогам.
* **Условие:** Попытка скачать файл по URL, резолвящемуся в `127.0.0.1`, `10.0.0.0/8`, `192.168.0.0/16`, `169.254.0.0/16` или `::1`.
* **Ожидаемый результат:** Адаптер прерывает загрузку с ошибкой SSRF validation error до открытия TCP-соединения; HTTP-запрос не отправляется.
* **Проверка:** `pytest -q tests/test_ssrf_download.py -k "test_private_dns_answer_is_never_fetched"` завершается с кодом 0.
* **Не входит:** Проверка репутации публичных IP-адресов.

### ID: SEC-WEBHOOK-01
* **Требование:** Webhook-сервер работает в режиме fail-closed: запросы без валидного секрета отклоняются до разбора тела JSON.
* **Условие:** На endpoint вебхука поступает POST-запрос с отсутствующим или неверным заголовком секрета (`X-Max-Bot-Secret`).
* **Ожидаемый результат:** Сервер немедленно возвращает HTTP 401/403 (или 503 при незаданном секрете на сервере); тело запроса не парсится; события не передаются в диспетчер.
* **Проверка:** `pytest -q tests/test_webhook_security.py -k "test_webhook_rejects_missing_or_invalid_secret"` завершается с кодом 0.
* **Не входит:** Защита от DDoS на уровне сетевого экрана.

### ID: SEC-SESSION-01
* **Требование:** Прямой доступ к управлению сессиями (`/sessions`, `/resume`) закрыт по умолчанию (deny-by-default) для пользователей не из allowlist.
* **Условие:** Пользователь, не входящий в список `allowed_users`, отправляет команду `/sessions` или `/resume <id>` при `allow_all_users=False`.
* **Ожидаемый результат:** Команда отклоняется; заголовки, ID и контекст чужих сессий не возвращаются.
* **Проверка:** `pytest -q tests/test_cross_session.py -k "test_unauthorized_user_cannot_list_or_resume_sessions"` завершается с кодом 0.
* **Не входит:** Ограничение доступа к истории текущего открытого диалога пользователя с ботом.

### ID: SEC-LIMIT-01
* **Требование:** Входящие медиафайлы скачиваются потоково с ограничением максимального объёма прочитанных байтов (streaming cap).
* **Условие:** Сервер отдает файл, превышающий установленный лимит (например, > 50 МБ) либо поток без заголовка `Content-Length`.
* **Ожидаемый результат:** Чтение прерывается при достижении лимита байтов; соединение закрывается; временный недокачанный файл удаляется с диска.
* **Проверка:** `pytest -q tests/test_inbound_media_limits.py -k "test_inbound_media_aborts_on_size_cap"` завершается с кодом 0.
* **Не входит:** Лимитирование размера исходящих загрузок в MAX API.
