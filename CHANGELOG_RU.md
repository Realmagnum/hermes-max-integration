# Журнал изменений

Все заметные изменения плагина hermes-max-integration.

## [2.10.2] — 2026-09-30

### Возможности и Hermes Desktop
- **Боковая панель сессий Hermes Desktop (`max-sessions-sidebar`):** добавлена встроенная панель MAX-сессий. Показывает активные диалоги, число сообщений, расход токенов, время и статусы.
- **Единый пакет и автоматическая установка:** backend и Desktop UI поставляются вместе; при включении плагина регистрируется `desktop/plugin.js`.
- **Локализация:** проверены русские переводы и английский fallback интерфейса Desktop.
- **Публичный репозиторий:** проект синхронизирован с [Realmagnum/hermes-max-integration](https://github.com/Realmagnum/hermes-max-integration).

### Исправления
- Исправлена обработка URL `file://` для изображений из Hermes Core.
- Восстановлены индикаторы действий в личных чатах; добавлено сопоставление `user_id` ↔ `chat_id`.
- Перед CDN-загрузкой медиа отправляются соответствующие chat actions.
- `stop_typing` сбрасывает индикатор через `typing_off`.

## [2.10.0] — 2026-09-29

### Безопасность и доступ
- **SEC-01:** callback авторизуется по владельцу, чату, сообщению и TTL.
- **SEC-02/03:** входящее медиа защищено DNS pinning; клиент загрузки не пересылает `Authorization` недоверенным хостам.
- **SEC-04:** webhook требует секрет, кроме явного loopback-only режима разработки; секрет проверяется до чтения тела.
- **SEC-05:** кроссплатформенные сессии выключены по умолчанию и доступны доверенным владельцам.
- **SEC-06:** allowlist групп fail-closed, условия пользователей и чатов объединяются через AND.
- **SEC-07:** ограничены размер и число вложений, общий объём, таймаут и параллелизм загрузки.

### Надёжность и транспорт
- **CODE-01:** polling использует backoff с jitter и учитывает `Retry-After`; 401 завершает polling без потока повторных ошибок.
- **CODE-02:** разбиение сообщений сохраняет пробелы, форматирование и fenced code blocks.
- **CODE-03:** streaming throttle изолирован по чату и сообщению; гарантирован flush.
- **CODE-04/06:** model picker поддерживает составные ID и привязывает состояние к владельцу/сообщению.
- **CODE-05:** разделены health (`/health`), readiness (`/ready`) и metrics (`/metrics`).
- **CODE-07:** lifecycle закрывает фоновые задачи и HTTP-клиенты.
- **CODE-08:** ingress-очередь, параллелизм и dedup ограничены настройками.

### Документация и качество
- Сверены переменные окружения и `platforms.max`; удалены несуществующие параметры.
- Добавлены проверки языковых ссылок, версии и числа тестов. Точный счётчик берётся из pytest текущего checkout.

## [2.9.0] — 2026-08-17

### Рефакторинг
- Монолитный `adapter.py` разделён на `mixins/`; адаптер стал фасадом над компонентами базового состояния, таблиц, медиа, кнопок, webhook, сессий и standalone-отправки.
- Внутри `mixins/` применяются относительные импорты; из `adapter.py` — `.mixins.xxx`, иначе загрузчик Hermes может не найти модули.
- Удалены дублирующее состояние сообщений, неэффективные обращения к коллекциям и исключения без логирования.

### Безопасность и исправления
- Добавлена `_validate_download_url()` для блокировки private/loopback/link-local/reserved IP, `localhost` и `*.local`.
- Отключено следование redirect при загрузке, чтобы не передавать токен стороннему хосту.
- Добавлено предупреждение при пустом `MAX_WEBHOOK_SECRET`.
- Ошибки JSON обрабатываются конкретными типами исключений.
- WAV/FLAC/M4A перед загрузкой нормализуются в Ogg/Opus через ffmpeg; блокирующее чтение файла вынесено из event loop.
- PNG-рендерер использует кэш по тексту таблицы и движку.
- Документация переведена на схему English base + `_RU`.

## [2.8.0] — 2026-08-05

### Изменено
- STT перенесён из плагина в Hermes Core (≥ 0.20.0): плагин скачивает и кэширует аудио, Core распознаёт его по настройкам `stt` в `config.yaml`.
- Удалены модуль `mixins/stt_processor.py`, скрипт `scripts/transcribe_audio.py` и параметры `MAX_STT_ENABLED` / `MAX_STT_VENV`.

### Рекомендации
- Для русского языка установите `stt.language: ru`; стандартный язык Core — `en`. Настройка доступна через `hermes tools` → STT.

## [2.7.1] — 2026-08-05

### Исправлено
- Исправлена работа STT в Windows: поиск интерпретатора Gateway, явные именованные аргументы `WhisperModel` и безопасная передача пути аудио через argv/переменную окружения.

### Рефакторинг
- STT-логика выделена в `mixins/stt_processor.py`; встроенный `_transcribe_media` удалён из `adapter.py`.

## [2.7.0] — 2026-07-25

### Добавлено
- Регистрация 20 slash-команд через `PATCH /me/commands` (лимит MAX — 32).
- Двухэтапный выбор модели с пагинацией.
- Динамическая ширина столбцов таблиц и inline Markdown в ячейках.
- `diagnose.sh` для проверки режима webhook/polling, порта, health, подписок и токена.
- Настройка отображения reasoning через `fresh_final_after_seconds`.

### Исправлено
- Откат выделения ModelPicker в отдельный модуль: это нарушало загрузку плагина.

## [2.6.0] — 2026-07-23

### Исправлено

- `send()` использует `body.mid` как резервный источник `message_id`.
- Ошибки polling теперь записываются в журнал.

### Документация
- Обновлены инструкции webhook и reverse proxy.

## [2.5.0] — 2026-07-23

### Добавлено
- Нативная отправка аудио и видео; токен берётся из ответа `/uploads`.
- Fallback на `type=file`, повтор при `attachment.not.ready`, allowlist upload URL.

### Исправлено

## [2.4.0] — 2026-07-22

### Добавлено
- `send_multiple_images()` отправляет несколько изображений одним сообщением; при ошибке используется последовательный fallback.
- `_standalone_send()` поддерживает изображения, видео, аудио и файлы через MAX upload protocol.

### Исправлено
- `_upload_send()` повторяет отправку при `attachment.not.ready` с backoff.
- `fu.oneme.ru` добавлен в SSRF allowlist.
- Исправлена standalone-отправка медиафайлов.
