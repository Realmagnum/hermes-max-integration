## Цель и границы

Создать в этом репозитории небольшой изолированный подпроект тестового стенда, запускающий настоящий Hermes gateway против детерминированной локальной замены сервиса MAX. Стенд обязан проверять чистую установку актуального Core и установку плагина штатным CLI Hermes, а не только импорт адаптера или имеющиеся unit-тесты. Симулируемый контракт отражает нынешние ожидания плагина; изменения реальных протоколов MAX учитываются только по факту. Не нужны рабочий токен бота, реальный адресат MAX, производственные подписки и публичный webhook. Существующие unit-тесты и CI сохраняются. Локальный симулятор не доказывает доставку через настоящий MAX или совместимость с будущим протоколом.

Выбор реализации (библиотека сервера, VM/LXC/контейнер и планировщик CI) относится к плану, а не к наблюдаемым контрактам. Управляющий API стенда не должен быть доступен извне изолированной сети. Нельзя ослаблять проверки URL медиа, DNS/SSRF и аутентификации или патчить Core ради тестов. Сейчас базовые URL API жёстко заданы в нескольких модулях плагина, поэтому безопасный способ подмены нужно отдельно спроектировать и протестировать; универсальная переменная окружения не подразумевается.

## Доказательства и передача

По этому контракту тесты не выполнялись. Существующий `MockMaxAPI` — внутрипроцессная фикстура `httpx.MockTransport`, а не отдельный HTTP-сервер; нынешний CI проверяет закреплённую матрицу Core и admission плагина, но не чистую установку из удалённого источника с запущенным gateway. Стенд должен расширять эту проверку, а не переименовывать старые результаты. Следующий разрешённый шаг — реализация после ознакомления с планом; этот документ не означает завершение работ.
