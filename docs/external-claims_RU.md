# Реестр внешних и неподтверждённых утверждений (DOC-10)

**Дата сверки источников:** 2026-09-16. Даты — исторические; перед практическим использованием перепроверьте внешние требования.
**Область:** утверждения о MAX API, требованиях платформы, возможностях Telegram и поведении Hermes Core в README и документации настройки.
**Метод:** сопоставление с официальной документацией MAX (`dev.max.ru/docs-api`), Telegram Bot API (`core.telegram.org/bots/api`) и исходниками Hermes Core 0.21.3 (`~/.hermes/hermes-agent`). Живые API-вызовы не выполнялись; production-токены и сообщения не использовались.

## 2. MAX API: адрес и авторизация

- **Адрес.** Согласно changelog MAX API, с **19 июля 2026 года** запросы должны идти на `https://platform-api2.max.ru` вместо `platform-api.max.ru`; корневой сертификат Минцифры следует добавить в хранилище доверия.
  - В проверенном checkout `MAX_API_BASE` задан как `platform-api2.max.ru`. Плагин содержит сертификаты Минцифры в `assets/certs/mincifry_bundle.pem` и настраивает SSLContext для httpx и aiohttp.
- **Авторизация.** Токен в query больше не поддерживается; нужен заголовок `Authorization`. Плагин использует заголовок (например, `adapter.py:345`).
- **Токен.** Выдаётся при создании бота через `business.max.ru/self` («Чат-боты») или приложение «MAX для бизнеса».

## 3. Требования для регистрации бота

Официальные требования: `dev.max.ru/help/platform_connection`.

- Регистрация доступна резидентам РФ: юридическим лицам, ИП и самозанятым.
- Физические лица без соответствующего статуса и нерезиденты не проходят проверку.
- Лимит ботов: **2** для самозанятых, **5** для организаций и ИП.
- Подтверждение профиля: Госуслуги для самозанятых; Госуслуги или банковские сервисы для организаций и ИП.

> В документации по установке следует явно предупредить: для регистрации MAX-бота нужен подтверждённый профиль резидента РФ.

## 4. Форматирование и лимиты

Официальный Markdown MAX (`dev.max.ru/docs-api`): курсив, жирный, зачёркивание, подчёркивание, моноширинный текст, ссылки, упоминания, выделение, заголовки и цитаты. HTML предоставляет сопоставимое форматирование. **Таблиц нет** ни в одном формате.

Лимиты (`dev.max.ru/docs-api`, POST /messages и POST /uploads):

| Параметр | Значение |
|---|---|
| Текст сообщения | до 4000 символов |
| Сообщения в один диалог/чат/канал | не более 2 в секунду |
| Запросы к `platform-api2.max.ru` | до 30 rps на интеграцию суммарно |
| Команды бота (`PATCH /me/commands`) | до 32 |
| Вложения в сообщении | до 12; `file` — только вместе с keyboard attachment, один файл |
| `image` | JPG/JPEG/PNG/GIF/TIFF/BMP/HEIC, ≤50 MB и ≤7680×7680 |
| `video` | MP4/MOV/MKV/WEBM, ≤250 MB |
| `audio` | MP3/WAV/M4A и другие, ≤256 MB и ≤60 минут |
| `file` | распространённые форматы (TXT, DOC, PDF и др.), ≤4 GB |

- Для неподдерживаемого типа возвращается `File extension is forbidden`; обещание «доставки любого расширения» неверно.
- `type=photo` больше не поддерживается — используйте `type=image`.
- `GET /chats` удалён в июне 2026 года; список чатов/каналов бота получают через `POST /subscriptions`.

## 5. Webhook: порт, TLS и CA

Официальные требования: `dev.max.ru/docs-api/methods/POST/subscriptions`.

- Endpoint должен быть доступен по **HTTPS только на порту 443**; порт не указывается в URL. Плагин слушает `8646` (`DEFAULT_WEBHOOK_PORT`), поэтому reverse proxy публикует его на 443. Примеры Caddy/Traefik — в `docs/setup_RU.md`.
- С **25 мая 2026 года** HTTP-webhook и self-signed сертификаты не поддерживаются. Сертификат должен быть от доверенного УЦ либо Минцифры; CN/SAN должен соответствовать домену, необходимо отдавать полную цепочку.
- Endpoint должен отвечать HTTP 200 за 30 секунд. Повторные попытки — до 10 с увеличивающимися интервалами; после 8 часов без успешного ответа подписка снимается автоматически.
- Заголовок `X-Max-Bot-Api-Secret`, если задан `secret`, должен содержать 5–256 символов `[A-Za-z0-9_-]`.
- **Для production рекомендуется webhook.** Long polling ограничен rate limit и сроком хранения событий и в документации назван неподходящим для production.
- `MAX_INSECURE_SSL` кодом плагина не используется (см. DOC-02); настройка этого флага не отключает проверку сертификата.

## 6. Telegram и нативные таблицы

- Обычные режимы (`Markdown`, `MarkdownV2`, `HTML`) поддерживают форматирование, но не таблицы.
- **Bot API 10.1 (11 июня 2026 года)** добавил Rich Messages: `RichBlockTable`, `RichBlockTableCell`, `sendRichMessage` и поле `rich_message` у `Message`. Таблицы доступны только через этот интерфейс.

## 7. Hermes Core 0.21.3: локальная проверка

- **Reasoning / fresh-final.** Ключ читается только из верхнеуровневой секции `streaming:` (`gateway/config.py`, `StreamingConfig.from_dict`) и применяется **только к Telegram**: `gateway/run_turn.py:2492` задаёт `0.0` для остальных платформ. Конфигурация `display.platforms.max.fresh_final_after_seconds` неверна и по пути ключа, и по применению к платформе.
- **Доставка media-only.** Исторические проверки обнаруживали ограничения маршрутизации в зависимости от версии Core. Плагин больше не поставляет обход с изменением Core. Проверяйте доставку через публичный router выбранного Core: unit-тест standalone sender не доказывает маршрутизацию media-only.

**Проверка router, 2026-10-13.** Интеграционные тесты на Core `ca13a7828acd2ba8c75e1c1d1694cbc1aee7df3f` используют настоящую регистрацию плагина и dispatch Core с подменёнными API/CDN транспортами (`tests/test_core_send_router.py`). Текст и текст с файлом доходят до зарегистрированного standalone sender MAX. Подтверждённая доставка вложений возвращает `media_delivered=true`, предотвращая предупреждение Core о неподдерживаемых вложениях. Отсутствующий файл, ошибка upload/CDN или отклонённая отправка вложения возвращают ошибку с `media_requested`, `media_sent`, `text_delivered` и `partial_delivery`; уже доставленные текст/файлы не выдаются за полный успех. Публичный `_send_to_platform` Core по-прежнему отклоняет MAX media-only до обращения к транспорту, хотя нижний dispatch `_send_via_adapter` умеет их доставлять. Эти изолированные проверки подтверждают маршрутизацию и смысл результата, но не реальную доставку MAX.
- **Лимит текста.** `MAX_MESSAGE_LENGTH = 4000` в `adapter.py` соответствует указанному лимиту MAX.
