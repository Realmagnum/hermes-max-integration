# Корреляция исходящих вложений — Micro-Spec

Источник: разрешённая задача диагностики PR10; контракт уточнён до одной итоговой completion/access-log записи. База: `52be4464700073b1a3bd49d9c5ac863e041c9828`. Core: локальный исходный дистрибутив0.0.0, точная SHA недоступна; это не evidence матрицы CI. Приёмка прежнего многострочного pin историческая, не приёмка нового контракта.

Scope: adapter image/video/audio/file, standalone, remote-image results и связь direct image batch upload→send/fallback. Delivery/retry/type не меняются; Core/config/launchd/logfile не правятся; builder не устанавливает, не рестартит и не публикует. Дальнейшие установка/live-приёмка/публикация принадлежат parent после review.

## Доказательства и ограничения

Накопитель использует фиксированные поля/счётчики и существующие обработчики, не cache событий или инфраструктуру. Batch до завершения держит по одному фиксированному накопителю на существующий вход (O(N) входов, O(1) каждый); глобального registry нет. Потеря при hard crash допустима. Source IDs — угадываемый mapping лексических путей, не анонимность/content checksum. До наблюдения source/artifact identities пусты, size -1, в том числе при ошибке подготовки и remote URL image. Счётчики/время насыщаются; слишком длинный ID сообщения пропускается только в summary. Mapping и поля описаны в [диагностике](../troubleshooting_RU.md#корреляция-исходящих-файлов). Live-доставка, установка, новое независимое review и матрица CI остаются pending.
