# Бэклог аудита: безопасность, реализация, документация

[English](BACKLOG_EN.md)

## Область и статус

База аудита: `b004c573318f1d5e521255531d1943cc8a8b8b90` (`main`). Все ссылки на строки ниже относятся к этой базе. Этот отдельный коммит сохраняет результаты аудитов до реализации исправлений. Все задачи открыты; изменение production, исправления кода и развёртывание не начаты. Ответственный пока не назначен.

Доказательства: **S** — статическое сопоставление кода/документов; **R** — изолированное выполнение извлечённых методов с моками (не полный плагин); **E** — реальная локальная команда; **V** — гипотеза или внешний контракт, требующий проверки. R-результаты получены независимыми ревьюерами; воспроизведения необходимо превратить в сохраняемые регрессионные тесты.

Фактически выполнено: чтение исходников и основных RU/EN-инструкций; изолированные проверки; попытка editable-install на Python 3.11.15; проверка локальных Markdown-ссылок и JSON-блоков. Полный pytest, Ruff, Bandit и pip-audit не запускались: пакетный запуск не получил подтверждения. Не проверены реальные MAX E2E, полная совместимость Hermes core, все внешние ссылки, актуальные правила платформ и вся история секретов. Отсутствие находки не означает отсутствие уязвимости.

## Порядок работ

1. Сохранить этот backlog отдельным коммитом (без исправлений).
2. Сделать воспроизводимыми сборку и тестовую среду (BUILD-01/02); сохранить failing regression tests для SEC.
3. Закрыть SEC-01…07, затем CODE-01…08; безопасную конфигурацию DOC-05 описать сразу вместе с защитами.
4. Сверить остальные документы, RU/EN и внешние контракты; обновить CI.
5. Пройти release gate ниже. Каждое исправление — отдельный тематический коммит с ID задачи; неизвестные контракты сначала проверить, не исправлять по предположению.

P1 — до публичного/multi-user использования; P2 — до следующего стабильного релиза. Приоритет не равен доказанности эксплуатации.

## Безопасность

- [ ] **SEC-01 · P1 · S/R — Авторизация callback подтверждений.** `adapter.py:1538–1640`, `mixins/buttons.py:225–227`: достаточно непустого user_id, approval хранит только session_key. Участник группы может подтвердить чужую опасную команду, включая always; аналогичный путь slash-confirm. Мок resolver получил owner-session от запрещённого пользователя. **Приёмка:** общая авторизация до dispatch/pop; состояние связано с owner_user_id/chat_id/message_id, TTL; чужой пользователь/чат/старая кнопка не вызывают resolver и не удаляют состояние. Проверить также clarify и model picker.
- [ ] **SEC-02 · P1 · S/R — Не передавать токен бота произвольному URL вложения.** `adapter.py:343–346, 975–1087`: audio/image/document GET содержит Authorization на исходном URL. Мок подтвердил передачу фиктивного токена чужому HTTPS origin. Условие — контроль URL принятого события; через обычный MAX-клиент не подтверждено, незащищённый webhook предоставляет путь. **Приёмка:** отдельный download-client без токена; только явно доверенный HTTPS origin получает авторизацию, если она необходима; тесты исходного URL и редиректов, отсутствие токена в ошибках/логах.
- [ ] **SEC-03 · P1 · S/R — SSRF при скачивании.** `adapter.py:930–947, 982–1069`: непонятный ipaddress hostname разрешается; DNS private/loopback не проверяется. Валидатор принял альтернативные loopback-формы. **Приёмка:** ограничить схемы/origins; при поддержке DNS проверять все A/AAAA и исключить rebinding на соединении; private/link-local/loopback/IPv6/нестандартные IP и редиректы покрыты тестами без обращения к настоящей внутренней сети.
- [ ] **SEC-04 · P1 · S — Webhook без секрета.** `adapter.py:221–230`, `mixins/webhook.py:63–116`: предупреждение вместо отказа, отправитель берётся из JSON. Публичный endpoint позволяет подделать разрешённый user_id. **Приёмка:** fail-closed без валидного секрета; проверка заголовка до обработки тела; явно отдельный loopback-only dev opt-in, если нужен; безопасные примеры и тесты отсутствующего/неверного секрета.
- [ ] **SEC-05 · P1 · S/R — Доступ к глобальным сессиям.** `adapter.py:201–205, 639–643, 712–732`, `mixins/sessions.py:42–106`: пустой allowlist при allow_all_users=False пропускает прямой /sessions до core; выдаются title/preview/ID всех платформ. **Приёмка:** deny-by-default до побочных эффектов; cross-session выключен по умолчанию либо owner-only с явным opt-in; тесты /sessions, search, /resume без аргумента и с аргументом. Проверить отдельно контракт core для resume; обход всех обычных сообщений не доказан.
- [ ] **SEC-06 · P1 · S/R — Семантика групповых allowlist.** `adapter.py:645–654`: пустой список даёт True, OR нейтрализует второй заданный список. **Приёмка:** определить OR/AND-политику, пустые списки не открывают доступ; матрица empty/set × user/chat × open/closed/allowlist, включая прямые команды.
- [ ] **SEC-07 · P2 · S — Лимиты входящих media.** `adapter.py:991–1087`: GET буферизует всё тело, 50 MB относится только к upload. **Приёмка:** streaming cap реально прочитанных байтов, общий дедлайн, число/сумма вложений, параллелизм и очистка частичных файлов; тесты без Content-Length, ложного размера, медленного/бесконечного ответа и переполнения диска.

## Качество реализации

- [ ] **CODE-01 · P1 · S/R — HTTP backoff polling.** `adapter.py:480–499`: HTTP 429/401/5xx не попадают в exception backoff; четыре mocked 429 дали четыре запроса без пауз. **Приёмка:** Retry-After, bounded exponential backoff/jitter, корректный fatal auth-state; virtual-clock тесты статусов и network errors.
- [x] **CODE-02 · P2 · S/R — Потеря текста при chunking.** `adapter.py:1114–1116, 1233–1236`: нумерация приводит к повторному обрезанию без переноса хвоста; 7800 входных символов → 7788 полезных выходных. **Приёмка:** префиксы учтены до разбиения; конкатенация отправленных payload сохраняет исходный текст; границы, Unicode, абзацы и код покрыты тестами. **Закрыто в `3126a08` (ветка `fix/code02-chunking`):** разбиение стало lossless (`"".join(chunks) == content`, без `.strip()` и пересборки слов), нумерация бюджетируется до разбиения, payload ≤ `MAX_MESSAGE_LENGTH`. `tests/test_chunking.py` на базе `b0ea511` — 44 failed, после исправления 60 passed; полный suite 202 passed / 6 pre-existing failures (tables/playwright, к задаче не относятся).
- [ ] **CODE-03 · P2 · S/R — Streaming isolation и flush.** `adapter.py:1298–1314`: throttle/pending общие для адаптера; два чата дали один PUT, pending сам не отправляется. **Приёмка:** состояние по сообщению/чату, гарантированный flush/finalize, корректная отмена таймеров; concurrent-chat и last-throttled-edit тесты.
- [ ] **CODE-04 · P2 · S/R — Model ID с двоеточием.** `adapter.py:1728–1758, 1881–1885`: llama3:8b разбирается как модель llama3 и provider 8b:ollama. **Приёмка:** непрозрачный ID либо однозначное кодирование; round-trip Ollama tags и OpenRouter :free, malformed/expired payload.
- [ ] **CODE-05 · P2 · S — Ложный connected webhook.** `mixins/webhook.py:138–152`, `adapter.py:350–375`: неуспех регистрации не блокирует connected; /me пропускает статусы кроме 401. **Приёмка:** проверить transport/HTTP/body success, очистить client/runner при ошибке; /health отделён от readiness; MockTransport сценарии 403/429/500/timeout/success=false.
- [ ] **CODE-06 · P2 · S — Изоляция model picker.** `adapter.py:1733–1736, 1824–1833, 1960–1978`: состояние только по чату; старое сообщение может применить новый callback. **Приёмка:** owner/session/message binding, TTL, stale-button tests, два пользователя/сессии в одном чате.
- [ ] **CODE-07 · P2 · S/V — Жизненный цикл и контракт core.** `adapter.py:267, 343–347, 390–405, 465–467, 505–519`: проверить repeated/concurrent connect, await отменённых задач перед закрытием клиента и inherited _mark_connected/_running. Последнее — непроверенный контракт, не доказанный сбой. **Приёмка:** pinned compatible core, connect→disconnect→connect и cancellation/finally tests; нет утечек клиентов/задач.
- [ ] **CODE-08 · P2 · S — Backpressure и dedup.** `adapter.py:263, 483–489, 517–519, 634–637`: очередь/число обработчиков не ограничены, pruning dedup удаляет старые записи, но не гарантирует заявленный hard cap свежих. **Приёмка:** bounded queue/concurrency/dedup, явная overload policy, burst/load tests и метрики.
